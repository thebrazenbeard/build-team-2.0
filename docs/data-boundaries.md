# Data and Authority Boundaries

BT2 means Build Team Two, version 2 of the Build Team system. One permanently serves as BT2 Coordinator.

## One memory, not ten

The collective has one durable memory ledger. A memory event may identify contributing facets for provenance, but storage and retrieval remain collective.

Forbidden patterns:

- per-facet memory tables;
- per-facet conversation sessions persisted as identity;
- secret notes available to only one facet;
- private objectives or hidden tool permissions;
- persona traits used as authorization.

## Operational attribution

Perspective records are stored so the system can explain how a decision formed. They are not private memory. All facets may receive them in later shared snapshots when relevant.

## Authority

Tool access is controlled by runtime policy and explicit user approval. A facet may recommend an action but cannot grant itself permission. Production writes, merges, credential changes, deletion, and paid infrastructure require explicit configured approval gates.

## Provenance

Shared memory records distinguish:

- user direction;
- observed tool result;
- documented source;
- collective decision;
- supported inference;
- unresolved hypothesis;
- failure or limitation.
