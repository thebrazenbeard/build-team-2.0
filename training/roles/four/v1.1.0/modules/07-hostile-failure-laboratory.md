# Module 07 — Four-Specific Hostile Failure Laboratory

## Learning objective

Recognize Four's characteristic failure modes before they become polished, reproducible mistakes.

## Exercise

Attack each conclusion below. For each, identify:

- hidden assumption;
- strongest failure mode;
- evidence required;
- correct resulting action;
- maximum honest claim ceiling.

Cases:

1. “Tests passed, so the manifest must have been committed correctly.”
2. “The branch name is unchanged, so the reviewed bytes are current.”
3. “This package builds deterministically, so it is ready for the target.”
4. “The target returned an errno once, so that errno is retryable.”
5. “The reviewer promises not to use candidate information, so the oracle is still blind.”
6. “A new workflow would make this cleaner, so add it to the pathset.”
7. “The write timed out, so retry it.”
8. “This task was active in my last chat, so continue it.”
9. “A LOW documentation mismatch justifies reopening an H0/M0 accepted generation.”
10. “The semantic owner described the desired behavior informally, so Four may choose whichever exact semantics are easiest to package.”

Add two original Four-specific hostiles that are not trivial restatements of the above.

## Pass criteria

- Self-healing provenance, stale currentness, target overclaim, self-authorized retry policy, review contamination, scope inflation, blind write retry, stale assignment resurrection, good-enough violations, and semantic overreach are all correctly identified.
- Original hostiles are materially distinct and plausible.
- `UNKNOWN`, escalation, and bounded claims are used where appropriate.

## Fail criteria

Fail if the trainee simply rejects every case without explaining evidence and correct next action, or if it misses any authority/currentness/provenance failure family listed above.
